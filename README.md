# Rice Mill Inventory Management and Demand Prediction

A Flask-based machine-learning application for estimating next-period rice demand and turning the prediction into a practical inventory decision. Users enter current mill information through a browser form and receive a demand estimate, stock assessment, coverage percentage, and reorder recommendation.

> **Project status:** Educational/demo application. The included dataset and model are reproducible examples and should not be treated as production planning advice without validation against real mill data.

## Overview

Rice mills need to balance customer demand, production, purchases, and warehouse stock. Too little inventory can lead to stockouts, while excessive inventory ties up cash and increases storage risk. This project predicts future rice demand from recent operational information and compares the prediction with current stock to provide a simple planning signal.

The application supports three rice types:

- **Basmati**
- **Sona Masuri**
- **Ponni**

The web interface is implemented with Flask, while the prediction pipeline uses pandas and scikit-learn. The trained pipeline is serialized with joblib and loaded by the application at startup.

## Features

- Browser-based form for entering current mill information.
- Demand prediction in kilograms for the next period.
- Time-derived features from the selected date: month, quarter, and year.
- One-hot encoding for rice type and standardization of numeric features.
- Comparison of Linear Regression, Random Forest, and Gradient Boosting regressors.
- Time-aware train/test split, using earlier observations for training and later observations for testing.
- Inventory labels for **Shortage Risk**, **Healthy Stock**, and **Excess Inventory**.
- Suggested reorder quantity based on predicted demand and a 20% safety-stock assumption.
- Saved model metrics in both CSV and JSON formats.

## How it works

The application follows this flow:

```text
data/rice_inventory.csv
        |
        v
src/preprocessing.py
(clean dates, numeric values, and engineer calendar features)
        |
        v
train_model.py
(compare regression pipelines on a time-aware split)
        |
        v
models/rice_demand_model.joblib
        |
        v
app.py
(load the trained pipeline and accept form inputs)
        |
        v
predicted demand -> stock assessment -> reorder recommendation
```

At prediction time, the Flask application builds one feature row from the submitted form, applies the saved preprocessing and regression pipeline, and clamps negative predictions to zero. It then compares the prediction with the submitted current stock.

## Dataset

The included `data/rice_inventory.csv` is a deterministic educational dataset generated by `data/generate_dataset.py` with random seed `42`.

| Property | Value |
|---|---|
| Observations | 108 monthly records |
| Date range | January 2022 through December 2024 |
| Rice types | Basmati, Sona Masuri, Ponni |
| Target | `future_demand_kg` |
| Units | Kilograms for quantities; currency units per kilogram for price |

### Input and target columns

| Column | Description | Used by model |
|---|---|---:|
| `date` | Monthly observation date | Converted into month, quarter, and year |
| `rice_type` | Rice category | Yes, categorical feature |
| `sales_kg` | Recent sales quantity | Yes |
| `production_kg` | Recent production quantity | Yes |
| `purchases_kg` | Recent purchases quantity | Yes |
| `current_stock_kg` | Current available stock | Yes |
| `price_per_kg` | Price per kilogram | Yes |
| `future_demand_kg` | Future demand in kilograms | Target only |

To use real operational data, replace the CSV while keeping the same column names and compatible values. Then regenerate the model as described below.

## Modeling approach

`train_model.py` performs the following steps:

1. Load the CSV and clean invalid dates and numeric values.
2. Derive `month`, `quarter`, and `year` from `date`.
3. Sort observations chronologically.
4. Use the first 80% of observations for training and the most recent 20% for testing. This avoids randomly mixing future observations into the training set.
5. Standardize numeric features with `StandardScaler`.
6. One-hot encode `rice_type` with unknown categories ignored at inference time.
7. Compare three regression estimators:
   - Linear Regression
   - Random Forest Regressor with 250 trees and maximum depth 8
   - Gradient Boosting Regressor with 180 estimators, maximum depth 2, and learning rate 0.05
8. Select the model with the lowest RMSE, using MAE as a tie-breaker.
9. Retrain the selected pipeline on the training partition and save it to `models/rice_demand_model.joblib`.
10. Save comparison results to `models/model_comparison.csv` and summary metadata to `models/metrics.json`.

## Evaluation results

The currently included artifacts were generated with 86 training rows and 22 test rows covering **2024-05-01 through 2024-12-01**.

| Model | MAE (kg) | RMSE (kg) | R² |

| Random Forest | 8.284 | 11.789 | 0.9772 |

## Running the application

If the included model artifacts are present, start the dashboard directly:

```bash

```

```bash

```

```text
http://127.0.0.1:5000
```

## Inventory decision rules

The Flask application uses the following simple rules after predicting demand:

1. **Safety stock:** `20% × predicted demand`.
2. **Suggested reorder quantity:** `max(0, predicted demand + safety stock − current stock)`.
3. **Shortage Risk:** current stock is below `80% × predicted demand`.
4. **Excess Inventory:** current stock is above `150% × predicted demand`.
5. **Healthy Stock:** current stock is between those two thresholds.

These thresholds are intentionally simple and should be adjusted for lead time, storage capacity, service-level targets, product shelf life, and purchasing constraints in a real operation.

## Limitations and production considerations

This project is a baseline demonstration, not a complete inventory-management system. The sample data is synthetic and covers only three years with one record per rice type per month. The model does not currently account for lead times, confirmed purchase orders, supplier reliability, warehouse capacity, promotions, holidays, quality grades, regional demand, spoilage, or stock commitments.

Before production use, consider collecting several years of validated transaction data, adding business-relevant features, using rolling or walk-forward validation, monitoring error by rice type and season, defining a retraining schedule, and adding authentication and input validation. Reorder decisions should also be reviewed by an inventory planner rather than executed automatically from the model output.

## Troubleshooting

### `ModuleNotFoundError: No module named ...`

Activate the virtual environment and install the dependencies again:

```bash
source .venv/bin/activate       # Linux/macOS
pip install -r requirements.txt
```

On Windows PowerShell, activate with `\.venv\Scripts\Activate.ps1` instead.

### `FileNotFoundError` for the model

Run the training script from the project root:

```bash
python train_model.py
```

The script creates or refreshes the files in `models/`.

### The model output changed after retraining

This is expected if the dataset or dependencies changed. The selected model and metrics are determined from the current training run and are recorded in `models/metrics.json` and `models/model_comparison.csv`.

### Invalid form values

Use a valid date and numeric values for every quantity and price field. The application displays an error message when a submitted value cannot be parsed.
